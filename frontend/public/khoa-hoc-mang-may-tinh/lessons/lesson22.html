Giao thức Web: HTTP và HTTPS

Mỗi lần bạn bấm vào một liên kết, HTTP/HTTPS chịu trách nhiệm đưa dữ liệu từ server về trình duyệt. Bài học này giúp bạn hiểu cách web vận hành và vì sao HTTPS là tiêu chuẩn bắt buộc.

Khái niệm

HTTP và HTTPS

📖 HTTP

Giao thức truyền dữ liệu giữa trình duyệt và web server, chạy trên TCP port 80.

🔒 HTTPS

HTTP kết hợp TLS/SSL để mã hóa, xác thực và đảm bảo toàn vẹn dữ liệu trên port 443.

⚠️ HTTP đặc trưng
  • Stateless.
  • Không mã hóa dữ liệu.
  • Dễ bị nghe lén nếu dùng dữ liệu nhạy cảm.

Nguyên lý

Request - Response & TLS Handshake

1. HTTP Request Trình duyệt gửi request (GET, POST...) đến server.
2. HTTP Response Server trả về HTML/CSS/JS hoặc dữ liệu API.
3. TLS Handshake Với HTTPS, client xác thực certificate và tạo khóa mã hóa.

So sánh

HTTP vs HTTPS

HTTP

  • Không mã hóa.
  • Dữ liệu dễ bị nghe lén.
  • Port 80.
  • Không có chứng chỉ số.

HTTPS

  • Mã hóa dữ liệu.
  • Xác thực danh tính website.
  • Port 443.
  • Tiêu chuẩn bắt buộc của web hiện đại.

Kỹ thuật

Phương thức HTTP & Status Code

HTTP Methods

  • GET: lấy dữ liệu.
  • POST: gửi dữ liệu.
  • PUT: cập nhật.
  • DELETE: xóa.
  • HEAD: kiểm tra.

Status Code

  • 2xx: thành công (200).
  • 3xx: chuyển hướng (301).
  • 4xx: lỗi client (404).
  • 5xx: lỗi server (500).

Request gồm

  • Method + URL.
  • Header.
  • Body (nếu có).

Kết luận:

HTTPS không chỉ là lựa chọn, mà là tiêu chuẩn bắt buộc cho web an toàn.

Thực hành

Tổng kết & bài tập

Thực hành nhanh trên trình duyệt:

  1. Truy cập một website bất kỳ.
  2. Kiểm tra HTTP hay HTTPS.
  3. Xem certificate được cấp bởi ai.
  4. Nêu điều gì xảy ra khi certificate hết hạn.
Gợi ý:

Trả lời ngắn gọn 5-7 dòng, tập trung vào bảo mật và trải nghiệm người dùng.
